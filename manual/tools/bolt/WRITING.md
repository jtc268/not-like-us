# Bolt writing guide

Bolt's generated copy often serves the first build rather than a durable product vocabulary.

## Common defaults to reject

- Unsupported hero promises and invented usage metrics.
- Generic navigation labels carried from starter applications.
- Empty states that sell the feature rather than explain the next action.
- Error text that hides whether data was saved.
- Demo content that can be mistaken for real accounts or activity.
- A marketing voice that leaks into operational controls.

## Better moves

- Define a glossary for entities, states, actions, and permissions.
- Separate promotional copy from task copy.
- Tell users what happened, what remains unchanged, and how to recover.
- Label sample content clearly.
- Replace every generic CTA with the action and object it affects.

Sources: [Bolt documentation](https://support.bolt.new/), [No AI Slop](https://github.com/petergyang/no-ai-slop), and [Wikipedia's maintained field guide](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing).
