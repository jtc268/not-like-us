# Universal design rules

Gradients, cards, Inter, and centered heroes can all fit a real brief. They become a problem when the tool selects them before learning what the product is. A cluster of defaults makes unrelated products converge on the same visual answer.

## Do not

1. **Invent a purple product.** Do not default to violet gradients, aurora blobs, blue-purple glows, or neon accents.
2. **Choose type by availability alone.** Inter, Geist, Playfair Display, Fraunces, Space Grotesk, and an italic display word are not neutral when used everywhere.
3. **Turn the page into a card collection.** Avoid nested cards, floating section wrappers, icon tiles, and rounded containers around content that already has structure.
4. **Reuse the startup landing sequence.** Centered hero, logo strip, three benefits, alternating features, metrics, testimonials, pricing, FAQ, and final CTA is not information architecture.
5. **Decorate without information.** Pills, sparkles, glass, shadows, mock charts, fake avatars, and floating dashboards need a job beyond signaling polish.
6. **Use one layout at every width.** Mobile is not the desktop page stacked into one long column. Preserve task priority and control reach.
7. **Apply one surface treatment everywhere.** If every object is rounded, elevated, outlined, and tinted, hierarchy disappears.
8. **Generate imagery as filler.** Generic teams, plastic faces, 3D blobs, and illegible interface mockups weaken trust.
9. **Animate the template.** Scroll fade-ups, logo marquees, count-ups, and hover lift should not be the default interaction model.
10. **Omit real states.** A polished happy path with no loading, error, empty, destructive, permission, or long-content states is not a finished interface.

## Do instead

- Begin with the user's primary task, the content model, and the existing brand.
- Derive hierarchy from frequency, risk, and sequence. Then choose layout.
- Use typography with a reason: reading conditions, language support, density, brand history, or data alignment.
- Let a few surfaces do more work. Use spacing and rules before containers and shadows.
- Show real copy and realistic data early. Test extremes, not only ideal samples.
- Make motion explain change, preserve context, or acknowledge input. Respect reduced motion.
- Use the portability test: if the same screenshot could market an unrelated AI startup after changing the logo, revise it.

The catalog draws on [OpenAI's frontend guidance](https://developers.openai.com/api/docs/guides/frontend-prompt), [Anthropic's documented Claude house style](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-4-8), [Unslop UI](https://github.com/claudiusararu/unslop-ui-skill), [AHD's slop taxonomy](https://github.com/Ad-Astra-Computing/ahd/blob/main/docs/SLOP_TAXONOMY.md), and [Anti AI Slop](https://github.com/Vinayak-Shukla-03/anti-ai-slop). These sources overlap and none is a controlled study, so each rule carries an evidence label.
