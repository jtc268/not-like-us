# Replit writing guide

Generated prototypes need enough copy to feel complete. That pressure can create fictional evidence and a vocabulary the real product cannot support.

## Common defaults to reject

- Invented testimonials, team activity, revenue, or customer logos.
- Broad hero promises unrelated to implemented behavior.
- Generic onboarding instructions that skip prerequisites.
- Errors that blame the user or conceal data loss.
- Sample data that looks live.

## Better moves

- Mark examples and seeded records clearly.
- Write onboarding from a clean account and test every step.
- Keep product claims within implemented, verified behavior.
- Explain recovery and persistence in errors.
- Replace placeholder copy before making layout decisions final.

Sources: [Replit Design Mode](https://replit.com/blog/design-mode), [No AI Slop](https://github.com/petergyang/no-ai-slop), and [Signs of AI Writing](https://github.com/egc365/signs-of-ai-writing).
