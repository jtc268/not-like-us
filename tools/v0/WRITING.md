# v0 writing guide

v0 often creates copy to satisfy a component tree. The component's expected length can become more important than the truth.

## Common defaults to reject

- Feature copy invented because a card component exists.
- Four-word headings paired with equal-length descriptions.
- Fake metrics and activity-feed items presented as product evidence.
- Generic actions such as “Explore,” “Get started,” and “View details.”
- Status badges whose language does not match the underlying process.
- Error and empty-state copy that never names the missing condition.

## Better moves

- Supply a content model with approved nouns, states, and actions.
- Remove any component that requires unsupported content.
- Write buttons for the resulting action, not the page's mood.
- Make labels match the domain vocabulary used by customers and support teams.
- Treat demo data as visibly fictional.

Sources: [v0 design systems](https://v0.dev/docs/design-systems), [No AI Slop](https://github.com/petergyang/no-ai-slop), and [Signs of AI Writing](https://github.com/egc365/signs-of-ai-writing).
